## 2. datastream_metadata

Datastream appends a RECORD column named `datastream_metadata` to each table in `raw_g2`:

| Field | BigQuery Type | Example | Meaning / Unit |
| --- | --- | --- | --- |
| `uuid` | `STRING` | `3786a80b-f920-4328-a03c-9adb274a4b1a` | Unique change event ID generated by Datastream |
| `source_timestamp` | `INTEGER` | `1795510091157` | Source transaction commit timestamp in **milliseconds (ms)** |
| `change_sequence_number` | `STRING` | `1a20cbdbd95/0/24eef48` | LSN-based change sequence. Sorts lexicographically as text |
| `change_type` | `STRING` | `INSERT`, `UPDATE`, `DELETE` | Operation type. Backfill rows arrive with `change_type = 'INSERT'` |
| `sort_keys` | `REPEATED STRING` | `["1795510091157", "0/24EEF48"]` | `[source_timestamp_ms, WAL_LSN]`. Primary tie-breaker |

## 3. Shapes of Change Events

Observed via live scratch testing on `g2.heartbeat` (`source = 'cdc-test'`):

### 3.1 Backfill Row
- Arrives with `change_type = 'INSERT'`.
- All table columns populated from the source table snapshot.
- Example metadata:
  ```json
  {
    "uuid": "5db21d43-86a9-4712-8afb-8f53297f69e9",
    "source_timestamp": 1795506181695,
    "change_sequence_number": "1a20c82163f/0/0",
    "change_type": "INSERT",
    "sort_keys": ["1795506181695", ""]
  }
  ```

### 3.2 INSERT
- `change_type`: `'INSERT'`
- All columns populated with their inserted values.
- Example:
  ```json
  {
    "source": "cdc-test",
    "beat_at": "2026-11-24 08:48:11",
    "updated_at": "2026-11-24 08:48:11",
    "datastream_metadata": {
      "uuid": "3786a80b-f920-4328-a03c-9adb274a4b1a",
      "source_timestamp": 1795510091157,
      "change_sequence_number": "1a20cbdbd95/0/24eef48",
      "change_type": "INSERT",
      "sort_keys": ["1795510091157", "0/24EEF48"]
    }
  }
  ```

### 3.3 UPDATE
- `change_type`: `'UPDATE'`
- **Single row:** Datastream emits exactly **one** row for an update, **not** an `UPDATE-DELETE` / `UPDATE-INSERT` pair.
- All columns contain their new values.
- Example:
  ```json
  {
    "source": "cdc-test",
    "beat_at": "2026-11-24 08:49:28",
    "updated_at": "2026-11-24 08:49:28",
    "datastream_metadata": {
      "uuid": "12e465bb-7d75-4250-85fa-8fed61d59381",
      "source_timestamp": 1795510168716,
      "change_sequence_number": "1a20cbeec8c/0/24f3648",
      "change_type": "UPDATE",
      "sort_keys": ["1795510168716", "0/24F3648"]
    }
  }
  ```

### 3.4 DELETE
- `change_type`: `'DELETE'`
- **Column values:** Under PostgreSQL `REPLICA IDENTITY DEFAULT`, **only the primary key columns** (`source`) are populated. All non-key columns (`beat_at`, `updated_at`) are `NULL`.
- Example:
  ```json
  {
    "source": "cdc-test",
    "beat_at": null,
    "updated_at": null,
    "datastream_metadata": {
      "uuid": "3ec4ba2d-cdf6-4f83-8bd4-6b18cbe8fce9",
      "source_timestamp": 1795510185598,
      "change_sequence_number": "1a20cbf2e7e/0/24f3770",
      "change_type": "DELETE",
      "sort_keys": ["1795510185598", "0/24F3770"]
    }
  }
  ```
- **Implication for dbt (A10):** The staging macro `cdc_current_state()` must reconstruct the last-known full image of a deleted record by taking the latest non-delete row, while setting `is_deleted = true` from the delete change row.
